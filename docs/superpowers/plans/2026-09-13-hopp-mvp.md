# Hopp MVP implementation and handoff

Resumed 2026-09-13 from Claude session `d9b722cc-c905-4ede-8387-8ec9e6fa26f6` after its usage limit. The original multi-agent plan workflow did not produce a final assembled plan. The approved design, mockups, research and original API captures were preserved and implementation proceeded in the bounded workstreams below.

**Goal:** Ship a static, phone-friendly Swiss journey planner that offers a researched sprint shortcut only when it leaves the full margin and beats the regular connection's arrival.

**Architecture:** Vite 6, strict vanilla TypeScript, zod 3, Bun unit tests, Playwright WebKit/Chromium. Static GitHub Pages at `/hopp/`; no application backend or credentials. See [approved spec](../specs/2026-09-13-hopp-design.md), especially §0 which overrides earlier prose.

## Decisions made while implementing

- The final user-selected default is **3.5 m/s**. Recomputed reference times replace obsolete 3.3 m/s examples. Margin configuration affects the model. UI spare means time left **after** sprint and margin.
- Research confidence is not field verification. Uncertain high-confidence route flags were lowered; missing landings are reported, never invented. Geometry and deliberately incomplete platform coverage remain visible in validation output.
- Candidates must begin with a rail journey at the shortcut station. Known missed onward transfers disqualify candidates. Unknown/ambiguous platforms never produce a GO.
- The live screen pins the selected scheduled service. Another train becoming catchable does not silently replace it.
- Explicit **Start sprint** distinguishes a rider who passed the stop from a runner already off the tram. The platform button is self-confirmation; it is not GPS boarding verification or an accepted competitive attempt.
- Mobile emulation is evidence for viewport and engine behavior, not a claim that every physical iPhone, Samsung Internet version, keyboard or home-screen installation has been tested.
- Route preview uses the retained OSM Zürich approach map; other approaches use an explicitly schematic route overview and real area link. Neither claims indoor turn-by-turn positioning.

## Subsequent phases preserved from the design

Week 2: offline service worker with network-only timetable data, GPS-selected next-tram entry and install/update prompts. Later: discovery miner, Cloudflare Worker/D1, actual commuter timings, profiles/points, GPS verification against the train's real-time movement, celebration animation and optional Strava. These are separate from the static MVP and have not been presented as working features.

Human field checks remain required to promote the desk-researched shortcuts. Use `docs/qa/think-aloud-script.md`; no actual commuter trial has been claimed.

## Expanded route research and copy corrections

The current catalogue has 11 enabled records and one Lausanne draft. Nine records were added after source checks across 40 stations: 25 approaches investigated in detail and 38 nearby-stop observations in a broader timetable screen. The [expansion report](../../research/2026-09-13-route-expansion.md) links exact sources, raw captures, public path chains and rejected alternatives. The real Winterthur Archstrasse → Aarau example is covered by both engine and browser regressions.

New hack files enter the bundle automatically through `scripts/build-catalogue.ts`. Partial platform coverage is allowed and tested; missing platforms stay unavailable. Bus feeders use bus stationboards, and origin-start routes no longer tell someone to get off a tram.

Removed the promotional tagline and marketing copy. Removed browse-all route discovery. Route notes and source links now belong to the specific searched trip. New route previews use actual stop/station names rather than the old Basel-specific schematic.

Final integration review fixed origin-only timing, fallback walking readiness, preservation of the selected train on confirmation, and automatic expiry of visible GO offers. The planner remains bounded to the earliest matched opportunity and one station candidate search; it does not claim to exhaust every possible route through every station.
